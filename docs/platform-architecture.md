# FloV:MP — платформенная архитектура (не готовый RP-сервер)

Уточнено владельцем 2026-09-10. FloV:MP = мультиплеер-**платформа** (движок + лаунчер),
которую продают RP-проектам. Платформа даёт возможность СОЗДАТЬ сервер и стабильную
игру. Владельцы серверов строят СВОИ системы. Мы НЕ поставляем готовый геймплей.

## Два уровня

### 1. Платформенная база (ships out-of-box, получает КАЖДЫЙ сервер)
Только инфраструктура:
- **Личность/аккаунты** — идентификация игрока (нужна для банов и хэндоффа лаунчера).
- **Бан-система** — HWID + HWID-Ex + Social Club + IP + подсеть /24 (+ MAC со стороны лаунчера). Флагман.
- **Войс** — проксимити-голос (`VoiceGridRouter` + встроенный войс alt:V).
- **Базовый чат** — обычные сообщения (без RP-команд).
- **Анти-чит** — движение/скорость/оружие/бой/транспорт (защита платформы).
- **Спавн** — появление в мире.
- **Удалённое управление** — приём команд из веб-кабинета (`RemoteServerAgent`).

### 2. RP-пример / SDK (НЕ платформа, отдельно, опционально)
Всё это — пример «что можно построить», не часть продукта:
экономика, инвентарь, фракции, жильё, документы, униформы, деньги-HUD,
RP-команды чата (`/me /do /pay /bank /faction`...), 8-уровневая RP-иерархия админов.
Сейчас ошибочно вшиты в «ядро» (`GamemodeResource`) — выносим в пример.

### Держава RP / Держава Онлайн
Базовый ТЕСТОВЫЙ сервер: полетать, посмотреть прогруз карты и лаги. На нём ничего
не строится. Урезать до платформенного минимума (спавн + мир), RP-начинку убрать
в пример.

## Бан-система (консолидация — сейчас фрагментирована)
Два дублирующих сервиса, оба НЕ подключены: `MultiTierBanService` (мультитир по
Account/IP/SC/HWID/MAC/Subnet) и `FlovIdPolicyService` (HWID + лимит мультиаккаунтов
+ режимы Strict/Lenient/Disabled). Консолидировать в один платформенный сервис:
1. **На коннекте снимать fingerprint:** `player.HardwareIdHash`, `HardwareIdExHash`,
   `SocialClubId`, `Ip` (всё есть в alt:V). **MAC — из лаунчера** (сервер MAC не
   видит; лаунчер шлёт при подключении, `DeviceInfoService`).
2. **Матчить** против активных банов (учёт срока) + политики FlovId (Strict блокирует,
   Lenient пускает+алертит, Disabled игнорирует аппаратные). Подсеть /24 — уже
   починена и покрыта тестами (2026-09-10).
3. **Команды** `/ban /banip /bansc /hwidban /macban /hardban` — создают правильный
   tier в сервисе (сейчас все лишь ставят `acc.IsBanned` — вводит в заблуждение).
4. **Персистентность:** баны переживают рестарт (таблица `punishments` в схеме уже
   есть; или bans.json). Для лицензии на проект — баны **общие на все ≤10 серверов
   проекта** (через портал/БД проекта).
5. **Enforcement подключать к потоку входа с fail-open** (ошибка проверки → пускаем,
   не блокируем логины) + живой тест перед деплоем.

## Веб-управление серверами (требование владельца)
Управление серверами через личный кабинет сайта FloV:MP ИЛИ сайт проекта. Основа
уже есть в схеме БД (`portal_users`, `portal_licenses`, `portal_launcher_builds`,
`portal_invoices`, `portal_telemetry`) и в коде (`RemoteServerAgent` принимает
удалённые команды, `TelemetryReporter` шлёт статус). Достроить:
- Портал (сайт): аккаунт владельца проекта → его лицензия → до 10 серверов.
- Каждый сервер регистрируется по ключу лицензии, шлёт телеметрию (онлайн, версия,
  здоровье) в портал, принимает команды (рестарт, бан/разбан, конфиг) через
  `RemoteServerAgent`.
- Управление банами/настройками сервера — из кабинета, применяется на сервере(ах).
См. модель лицензий: 1 лицензия/проект, до 10 серверов, веб-панель.
