# Срез проверки VDS с Mac — 26.09.2026

Проверено через redl API без переустановки сервера и без изменения лицензий.
Токен доступа в репозиторий и команды не записывался.

- `flovmp`, `flovmp-voice`, `flovmp-license`, `mariadb`, `nginx` работают.
  Публичный `/info` отвечает `online=true`, геймод `RolePlay`, 0/2000 игроков;
  `/api/v1/license/health` отвечает HTTP 200.
- Живой healthcheck: 68 проверок, 0 провалов и 0 предупреждений при фактическом
  голосовом порте `7795`. Порт `7788/TCP` доступен, `7795/UDP` не отклонён.
  Это не заменяет вход в GTA и нагрузочный тест.
- Игровой сервер слушает `7788` и шлюз `7798`; MariaDB (`3306`) и внутренний
  API лицензий (`7800`) слушают localhost. Диск: около 62% занято, RAM 4 ГБ,
  доступно около 3.6 ГБ на момент проверки.
- В `/root/backups/db/20260926/` есть дампы `flovmp` и `flovmp_licensing`.
  Отдельная служба `flovmp-db-backup` активна и запускает ночной скрипт в
  03:30; на этой машине systemd timers не поддерживаются провайдером.
  Старый `flovmp-backup.timer` помечен enabled, но не стартует по этой причине.
  Вручную выполнен штатный `/opt/flovmp/scripts/backup-db.sh`: дамп
  `flovmp_server` создан, gzip проверен, в нём 6 таблиц. Базы `flovmp` и
  `flovmp_server` здесь различаются; ночной скрипт покрывает `flovmp`.
- Базы портала `flovmp_portal` на этой VDS нет. Миграция
  `sql/portal_migrations/001_platform_core.sql` на VDS не применялась:
  центральный портал и игровая БД должны оставаться раздельными.
