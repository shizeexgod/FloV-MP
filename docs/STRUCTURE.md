# Архитектура и структура шаблона проекта (Scaffold) — FloV:MP

## 1. Концепция поставки (Scaffold / Готовый шаблон проекта)

FloV:MP поставляется разработчикам RP-проектов в виде готового автономного дистрибутива («коробки»). Разработчик стороннего RP-проекта получает чистый каркас, содержащий преднастроенное высокопроизводительное серверное ядро, клиентский стек с NUI-интерфейсами, схему базы данных и набор служебных скриптов управления.

Главный принцип: **полное разделение движка (FloV:MP) и RP-проекта**. Движок работает автономно, поддерживает до 2000+ одновременных игроков, предоставляет White-Label архитектуру (игроки видят только бренд конкретного RP-проекта) и лицензируется через криптографический файл `license.flv`.

## 3. Настройка White-Label и брендинга

Движок FloV:MP поддерживает динамическое брендирование. При запуске сервер автоматически считывает имя сервера и передаёт его клиентам:

1. **Через `config/server.toml`**:
   ```toml
   name = "Moscow RolePlay"
   description = "Highload RolePlay Server"
   website = "moscow-rp.ru"
   players = 2000
   ```

2. **Через переменную окружения `FLOVMP_SERVER_NAME`**:
   ```bash
   export FLOVMP_SERVER_NAME="Moscow RolePlay"
   ```
   Если задана переменная окружения, она имеет наивысший приоритет и отображается в заголовке NUI-авторизации, игровом HUD и приветственном сообщении чата.

## 4. Конфигурация высокой нагрузки (2000+ слотов)

Конфигурационный файл `config/server.toml` оптимизирован под стабильную работу при 2000+ онлайна:

- `streamingDistance = 250` — радиус стриминга сущностей в метрах.
- `migrationDistance = 120` — дистанция передачи авторитета сетевой синхронизации.
- `colShapeTickRate = 300` — частота проверки триггерных зон коллизий (мс).
- `[maxStreaming]` — лимиты сущностей на одного клиента:
  - `peds = 48`
  - `vehicles = 48`
  - `objects = 64`
- `[threads]` — многопоточная обработка сетевого конвейера:
  - `streamer = 2` — выделенные потоки пространственной выборки PVS.
  - `migration = 1` — поток миграции сетевых сущностей.
  - `syncSend = 1` — поток отправки исходящих пакетов синхронизации.
  - `syncReceive = 1` — поток входящих сетевых пакетов.

## 5. База данных (MariaDB / MySQL)

В каталоге `sql/schema.sql` находится чистая реляционная схема базы данных с внешними ключами и составными индексами:
- `accounts` — учётные записи игроков (логин, BCrypt-хэш, HWID, Social Club ID, TOTP 2FA).
- `characters` — игровые персонажи (баланс наличных, банковский счёт, позиция X/Y/Z/Heading, кастомизация).
- `character_inventory` — инвентарь (слоты, типы предметов, вес, сериализованные метаданные).
- `vehicles` — личный и фракционный транспорт (модель, номерной знак, цвет, пробег, тюнинг).
- `houses` — жилая недвижимость (стоимость, координаты входа, гаражные места).
- `factions` — государственные и криминальные организации (ранги, бюджет).
- `audit_logs` — журнал безопасности действий администрации и финансовых операций.
- `bans` — система блокировок (по аккаунту, IP, HWID).

Подключение к базе данных настраивается через переменную окружения `FLOVMP_DB_CONNECTION`:
```
FLOVMP_DB_CONNECTION="Server=127.0.0.1;Port=3306;Database=flovmp_rp;Uid=root;Pwd=secret;"
```
При отсутствии соединения с MariaDB сервер автоматически переключается на локальное отказоустойчивое хранилище JSON (`data/accounts_fallback.json`), что предотвращает падение процесса при сбоях СУБД.

## 6. Лицензирование (`license.flv`)

Файл `license.flv` содержит RSA-2048 криптографическую подпись.
Сервер проверяет лицензию локально при старте без обязательного внешнего соединения, обеспечивая 100% автономность.
Параметры лицензии:
- Лицензионный ключ (`licenseKey`, формат `FLV-XXXX-XXXX-XXXX`)
- Название проекта (`project`)
- Тарифный план (`plan`: standard, professional, enterprise)
- Максимальное количество игроков (`maxPlayers`: 500 – 5000)
- Срок действия (`expiresAt`)

## 7. Расширение логики и разработка RP-геймплея

Разработчик проекта может создавать собственные C# сборки и подключать их к FloV:MP:
1. Создать проект C# Class Library (.NET 8).
2. Подключить зависимость от `FloVMP.Core.dll` (из `server/resources/flovmp-core/`).
3. Зарегистрировать собственные подсистемы через интерфейсы `FloVMP.Core`:
   - Наследование от `FloVMP.Core.Systems`
   - Использование `SpatialHashGrid` для гео-запросов за $O(1)$
   - Регистрация событий клиента через безопасные обёртки `Safe.Run`
4. Скомпилировать DLL и поместить в `server/resources/flovmp-core/`.
