# Огонь и взрывы: протокол (пункт 22b) — ЧЕРНОВИК НА СОГЛАСОВАНИЕ

Статус: только описание. Код — после согласования с владельцем.
Относится к клиентам GTA V Legacy 1.0.3889.0 (наш ASI). Клиенты alt:V —
отдельно, в конце.

Нативы, на которые опирается протокол, сверены с базой нативов
(alloc8or/gta5-nativedb-data): `ADD_EXPLOSION(..., BOOL noDamage)`,
`START_SCRIPT_FIRE`, `STOP_FIRE_IN_RANGE`, `GET_NUMBER_OF_FIRES_IN_RANGE`,
`IS_EXPLOSION_IN_SPHERE`, `IS_PROJECTILE_TYPE_IN_AREA`,
`HAS_ENTITY_BEEN_DAMAGED_BY_WEAPON`; хэши `WEAPON_EXPLOSION` = 0x2024F4E8,
`WEAPON_FIRE` = 0xDF8E89EB. Поведение на 3889 — проверить в игре.

## 1. Как сейчас (проверено по коду, 25.09.2026)

- Урон по другим игрокам считает **клиент стрелка** (`DetectHits` в
  `game.cpp`): у него копия чужого игрока потеряла здоровье «от меня или моей
  машины» — он шлёт `HIT жертва оружие урон`. Сервер проверяет попадание
  античитом, спрашивает геймод (`flovmp:damage`, решение — в следующем тике,
  пункт 22) и сам списывает здоровье.
- Поле «оружие» в `HIT` — **то, что у стрелка в руках** (`GET_SELECTED_PED_WEAPON`),
  а не настоящая причина урона. Граната, брошенная секунду назад, засчитается
  как оружие, на которое игрок уже переключился.
- **Взрывы и огонь другим игрокам не передаются вовсе.** Взрыв, пожар, коктейль
  Молотова существуют только в игре того, кто их вызвал. Остальные видят, что
  игрок теряет здоровье, но не видят, от чего.
- Урон жертве от огня и взрывов, **не приписанных игроку** (взорвалась машина,
  горит бензин, пожар без владельца), в `flovmp:damage` не попадает: жертва
  сама сообщает сниженное здоровье в `STATE`, сервер принимает понижение.

## 2. Что можно перехватить, а что нет — честно

| Что | Можно? | Как и какой ценой |
|---|---|---|
| **Урон игроку от взрыва/огня, вызванного другим игроком** | **Да**, как пули | тот же `flovmp:damage`, решение в следующем тике; нужно передать причину (п. 3.1) |
| **Урон игроку от «ничейного» огня/взрыва** | **Частично** | жертва сообщает причину; отменить можно только **после** — сервер возвращает здоровье (`HEALTH`), игрок видит мигание полоски на ~1 тик+пинг |
| **Сам взрыв у того, кто его вызвал** | **Нет** | эффект рождается в GTA стрелка раньше, чем сервер о нём узнаёт. Синхронно отменить нечего |
| **Взрыв у остальных игроков** | **Да** | сервер пересылает взрыв остальным только после решения геймода: отменил — остальные его не увидят (стрелок — увидит) |
| **Огонь (пожар) после появления** | **Только тушение** | сервер велит клиенту-владельцу и остальным потушить (`STOP_FIRE_IN_RANGE`); огонь виден ~пинг+тик (50–150 мс) |
| **Не дать вообще взорвать/поджечь** (сейфзона, режим) | **Только заранее и только на клиенте** | сервер присылает правила (зоны, запрещённые типы) — клиент не даёт бросить/выстрелить. Честный клиент послушается, чит — нет; урон по игрокам всё равно проверяет сервер |
| **Взрыв машины** | уже есть | машина реестра, здоровье ≤ −4000 → событие «уничтожена» (8c); отменить взрыв нельзя, запретить урон машине — отдельная задача |

## 3. Предлагаемый протокол (клиент 1.0.11+)

### 3.1. Причина урона в HIT

`HIT жертва оружие урон [причина]` — пятое поле: `bullet`, `melee`, `vehicle`,
`explosion`, `fire`. Клиент определяет её по
`HAS_ENTITY_BEEN_DAMAGED_BY_WEAPON` (общие хэши `WEAPON_EXPLOSION`
0x2024F4E8 и `WEAPON_FIRE` 0xDF8E89EB), для взрыва — тип взрыва. Старые
клиенты поле не шлют — сервер считает `bullet`, как сейчас.

Геймоду — **то же событие** `flovmp:damage` (подпись не меняется), в поле
`weapon` приходит `WEAPON_EXPLOSION`/`WEAPON_FIRE` вместо оружия в руках.
Плюс новое `flovmp:damage:cause (request, cause, explosionType)` сразу после —
для тех, кому нужна подробность. Существующие геймоды продолжают работать.

Античит: взрыв/огонь засчитывается, только если у стрелка по учёту сервера
было взрывное оружие (граната, РПГ, липкая бомба, Молотов) или он в машине,
и в пределах радиуса взрыва (≈ 15 м для гранаты, до 25 м для тяжёлых) —
иначе это подделка `HIT`.

### 3.2. Взрыв — остальным

- Клиент → сервер: `EXPL x y z тип` — взрыв, который вызвал этот игрок
  (обнаружение раз в тик: `IS_PROJECTILE_TYPE_IN_AREA(..., ownedByPlayer = TRUE)`
  — где летят свои снаряды, затем `IS_EXPLOSION_IN_SPHERE` там, где снаряд
  пропал; клиент видит только свои взрывы).
- Сервер: античит (частота ≤ 5/с на игрока, тип совместим с оружием, точка
  в радиусе досягаемости) → геймоду `flovmp:explosion (request, playerId, x, y, z, type)`
  → решение в следующем тике: `flovmp:explosion:set (request, allow)`.
- Разрешено → сервер → игрокам в радиусе видимости: `EXPL x y z тип владелец`.
  Клиент рисует **без урона** (`ADD_EXPLOSION(..., noDamage = TRUE)`): урон
  считает сервер по `HIT` (3.1), иначе он пришёл бы дважды.
- Отменено → остальные взрыва не видят. У самого стрелка он уже был.

### 3.3. Огонь — остальным и тушение

- Клиент → сервер: `FIRE x y z радиус` для огня своего игрока (опрос
  `GET_NUMBER_OF_FIRES_IN_RANGE` вокруг своих снарядов/машины), не чаще
  раза в 500 мс на точку.
- Сервер → геймоду `flovmp:fire (request, playerId, x, y, z)` → решение в
  следующем тике.
- Разрешено → остальным `FIRE x y z радиус длительность` (визуальный
  `START_SCRIPT_FIRE`, гаснет сам). Отменено → стрелку и всем
  `FIREOUT x y z радиус` (`STOP_FIRE_IN_RANGE`).
- Геймод может потушить в любой момент: `flovmp:fire:extinguish (x, y, z, радиус)`.

### 3.4. Урон от «ничейного» огня/взрыва

Клиент жертвы при потере здоровья от огня/взрыва без виновного шлёт
`SELFDMG причина урон`. Сервер → геймоду `flovmp:damage` с attackerId = 0 и
причиной. Отмена = сервер возвращает здоровье следующим `HEALTH` (игрок видит
мигание полоски). Без ответа — как сейчас.

### 3.5. Правила заранее (необязательно)

`flovmp:explosions:rules (zonesJson, forbiddenTypesCsv)` — сервер рассылает
клиентам: в зонах клиент не даёт бросить/выстрелить взрывным и тушит огонь
сразу. Это удобство для честных игроков, не защита.

## 4. Цена

- Трафик: `EXPL`/`FIRE` — десятки байт на событие, только игрокам в радиусе
  видимости; при 1000 онлайн и активном бое — единицы КБ/с на сервер.
- Задержка: урон — +1 тик (как пункт 22); взрыв у остальных — пинг стрелка +
  тик + пинг зрителя (обычно 60–150 мс); тушение — столько же.
- Клиент: опрос снарядов/огня своего игрока раз в тик — копейки; рисование
  чужих взрывов — штатные нативы.
- Изменения: `game.cpp` (обнаружение, рисование, причина в HIT), сервер
  (сообщения, античит, события), протокол FLOV/2 растёт на 5 строк.
- Риск: нативы обнаружения огня/взрыва на 3889 надо проверить в игре —
  хэши сверить с базой нативов, поведение — живым прогоном с двумя
  клиентами (у владельца).

## 5. Клиенты alt:V (смешанный режим)

У alt:V есть штатные `Alt.OnExplosion` и `Alt.OnFire`/`OnStartFire` с правом
отмены **в том же вызове**. Платформа тут не посредник: геймод подписывается
на них сам, в своём ресурсе (Alt.Emit через платформу опоздал бы — доставка
после тика, 7d932ab). Отмена у alt:V тоже не убирает взрыв у стрелка — только
у остальных.

   даёт геймоду «броню от взрывов» и «огонь не наносит урона в сейфзоне».
2. Нужна ли синхронизация взрывов и огня для остальных (3.2–3.3) сейчас?
   Это самая большая часть и главное видимое изменение («все видят взрыв»).
3. «Ничейный» урон (3.4) с миганием полоски при отмене — приемлемо?
4. Правила заранее (3.5) — делать или хватит серверной отмены урона?
