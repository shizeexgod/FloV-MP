# Установка на Windows-VDS клиента: как это устроено

Для владельца FloV:MP. Описывает оба способа установки у клиента на Windows,
что происходит на каждом шаге и что клиент видит на экране.

Файлы:

| Что | Где в репозитории | Где у клиента |
|---|---|---|
| Архив установки | `scripts/package-templates/setup-zip/` → `dist/cdn/flovmp-setup.zip` | `http://<VDS>/cdn/flovmp-setup.zip` |
| Загрузчик | `scripts/distribution/get.ps1` | `http://<VDS>/cdn/get.ps1` |
| Установщик (внутри пакета) | `scripts/package-templates/windows/install.ps1` | распаковывается во временную папку |
| Сборка архива | `scripts/distribution/make_setup_zip.py` | — |

Архив установки и загрузчик **не содержат сервера**. Они скачивают последний
релиз по ключу лицензии, поэтому не устаревают: выпустили новую версию —
клиенты ставят её теми же файлами.

---

## Способ 1. Архив в один клик

Клиенту даётся ссылка на `flovmp-setup.zip` (~8 КБ).

Что внутри:

```
УСТАНОВИТЬ.cmd      двойной щелчок
flovmp-setup.ps1    диалог: папка и ключ, память о прошлом запуске
get.ps1             загрузчик с вшитым открытым ключом релизов
ПРОЧТИ-МЕНЯ.txt     инструкция на одну страницу
настройки.txt       появляется после первого запуска
```

**Как это видит клиент.** Распаковывает архив в папку будущего сервера
(например `C:\FloVMP`), щёлкает `УСТАНОВИТЬ.cmd`, видит:

```
  FloV:MP — установка и обновление сервера
  ----------------------------------------

  Папка сервера [C:\FloVMP]
  Enter — оставить, либо введите другой путь:

  Ключ лицензии выдаётся при покупке и выглядит так:
  FLV-1A2B3C4D-5E6F7A8B-9C0D1E2F-3A4B5C6D
  Ключ лицензии: ____

Папка установки: C:\FloVMP
==> Релиз FloV:MP
  подпись релиза верна
  версия 1.0.4, пакет flovmp-server-1.0.4-windows.zip
==> Скачивание пакета
  SHA-256 совпал
==> Установка
[1/4] Проверка исходного пакета (72 файлов)...
[2/4] Подготовка временной копии...
[3/4] Резервная копия старой платформы и установка...
[4/4] Повторная проверка установленной платформы...
Лицензионный ключ сохранён в config\flovmp.env.
Готово: C:\FloVMP

  Дальше:
  1. запустите сервер: C:\FloVMP\FloVMP-Server.exe
  2. настройки сервера — server\server.toml и server\config\client.cfg
  3. обновление — просто запустите этот же файл ещё раз

Готово.
Нажмите любую клавишу...
```

Окно не закрывается само (`pause`), поэтому клиент успевает прочитать ошибку,
если она была.

**Защита от глупых мест установки.** Если архив распакован в «Загрузки»,
«Рабочий стол», «Документы» или `Temp`, скрипт предупреждает и предлагает
ввести другой путь. Папку всегда можно переопределить прямо в диалоге.

**Память между запусками.** После успешного запуска рядом появляется
`настройки.txt`:

```
ключ = FLV-...
папка = C:\FloVMP
адрес = http://188.127.229.224
```

Второй щелчок — уже обновление без единого вопроса.

**Автообновление.** `УСТАНОВИТЬ.cmd -Quiet` не задаёт вопросов: годится для
планировщика заданий Windows (раз в сутки ночью).

## Способ 2. Одна команда

### Откуда берётся пакет

Загрузчик умеет две раздачи:

| Источник | Команда | Когда |
|---|---|---|
| VDS владельца | `.\get.ps1 -Key FLV-...` | по умолчанию, пакет отдаёт сервер лицензий по ключу |
| GitHub-релиз | `.\get.ps1 -GitHub shizeexgod/FloV-MP-releases -Key FLV-...` | когда канал VDS медленный или пакет раздаётся публично |

Подпись релиза проверяется одинаково в обоих случаях — подменить пакет нельзя
ни на VDS, ни на GitHub. Разница только в том, кто отдаёт файл.


Клиенту даётся строка, которую он выполняет в папке будущего сервера:

```powershell
cd C:\FloVMP
powershell -ExecutionPolicy Bypass -Command "iwr http://188.127.229.224/cdn/get.ps1 -OutFile get.ps1; .\get.ps1 -Key FLV-XXXXXXXX-XXXXXXXX-XXXXXXXX-XXXXXXXX"
```

Без `-InstallDir` установка идёт **в текущую папку** — ровно туда, куда клиент
зашёл через `cd`. Системные папки (`Windows`, `System32`, `Program Files`,
корень профиля) отклоняются с объяснением.

Обновление потом: `.\get.ps1` без ключа — ключ берётся из установленного
`config\flovmp.env`.

Ключи загрузчика: `-Key`, `-InstallDir`, `-Dist` (другой адрес раздачи),
`-Reinstall` (переустановить ту же версию), `-Force` (см. ниже), `-NoStart`.

## Что происходит внутри (оба способа)

1. **Описание релиза.** `GET /api/v1/distribution/release?os=windows&key=<ключ>`
   — сервер лицензий проверяет ключ (не найден, приостановлен, отозван,
   истёк → 403 с причиной) и отдаёт `release-windows.txt`: версия, имя файла,
   SHA-256, размер.
2. **Подпись.** Рядом скачивается `release-windows.txt.sig` — RSA-3072 подпись
   закрытым ключом релизов, который лежит **только** на ПК владельца
   (`%USERPROFILE%\.flovmp\release-signing.pem`). Открытая часть вшита в
   `get.ps1`. Подпись не сошлась — установка останавливается: значит описание
   подменили по дороге (HTTP) или на самом VDS.
3. **Нужно ли обновление.** Если в папке уже есть `manifest.json` с той же
   версией — ничего не скачивается: «Обновление не требуется».
4. **Пакет.** `GET /api/v1/distribution/download?...` — файл отдаёт nginx
   (`X-Accel-Redirect`), служба не занимает поток. SHA-256 сверяется с тем,
   что был в подписанном описании. Не сошёлся — стоп.
5. **Установка.** Из пакета запускается `install.ps1` — тот же, что в ручной
   установке из архива:
   - проверяет SHA-256 каждого из 72 файлов пакета **до** того, как что-то
     тронуть в папке клиента;
   - ищет столкновения с чужими файлами (см. ниже);
   - собирает новую версию во временной папке `.flovmp-stage-...` рядом;
   - копирует старые файлы платформы в `.flovmp-backup-ДАТА`;
   - удаляет только те файлы платформы, которых нет в новой версии;
   - копирует новые файлы и **перепроверяет SHA-256 уже на месте**;
   - при любой ошибке возвращает прежнюю версию из резервной копии;
   - записывает ключ и адрес сервера лицензий в `config\flovmp.env`.
6. **Активация.** Сам сервер при первом запуске обращается к серверу лицензий,
   получает `license.flv` и дальше раз в 5 минут продлевает подтверждение
   (24 часа запаса на сбои связи).

## Безопасность для папки клиента

Главное правило: **платформа знает свои файлы поимённо и трогает только их.**
Список — `manifest.txt` в корне установки (путь + SHA-256).

| Ситуация | Что делает установщик |
|---|---|
| Папка пустая | ставит |
| В папке уже FloV:MP (есть `manifest.txt`) | обновляет: копия старого → замена → проверка; лишние файлы прошлой версии удаляются |
| В папке чужой сервер/мод, имена не совпадают | ставит рядом, предупредив «посторонние файлы не трогаем» |
| В папке чужой сервер/мод, имена совпадают | **останавливается**, показывает список совпавших файлов, ничего не меняет |
| То же с `-Force` | копирует чужие файлы в `.flovmp-backup-ДАТА` и только потом заменяет |
| Ошибка в середине установки | возвращает прежнюю версию из резервной копии; если папки раньше не было — удаляет созданную |

Никогда не затрагиваются (их нет в `manifest.txt`): `config\flovmp.env`,
`license.flv`, `server\server.toml`, `server\config\*` (`client.cfg`,
`admins.json`, `admin-commands.cfg`, `maps`), папка `gamemode`, ваши ресурсы в
`server\resources`, миграции с номера 100, база и резервные копии.

Пути из `manifest.txt` проверяются построчно: абсолютный путь, `..`, `:`
(альтернативные потоки NTFS) и выход за корень отклоняются — подсунуть
манифест, который пишет в `C:\Windows`, нельзя.

## Как выпустить обновление (владелец)

```powershell
python scripts/pack_server.py                          # собрать пакеты
python scripts/distribution/sign_release.py --out dist/release-1.0.4
$env:REDL_TOKEN = "redl_pat_..."
python scripts/distribution/publish_release_vds.py dist/release-1.0.4
```

Архив установки пересобирать не нужно — он ссылается на «последний релиз».
Пересборка требуется, только если менялся сам `get.ps1` или ключ релизов:

```powershell
python scripts/distribution/make_setup_zip.py          # dist/cdn/flovmp-setup.zip
python scripts/distribution/make_vds_bundle.py         # кладёт его в комплект VDS
python scripts/distribution/deploy_vds.py              # setup-vds.sh положит в /var/www/cdn
```

Клиенты получают новую версию, запустив `УСТАНОВИТЬ.cmd` (или `.\get.ps1`).
Старые установки продолжают работать: сервер лицензий отдаёт только текущий
релиз, но никого не заставляет обновляться.
