2. НАЙДЕННЫЕ ДЕФЕКТЫ В НОВОМ CEF API
=====================================

[P1] 2.1. Залипшее состояние focus после закрытия cursor/UI
----------------------------------------------------------

Файл:
  native/legacy-3889/client/src/browser.cpp

Место:
  SetInput(bool enabled), около строк 813–824.

Сейчас при SetInput(false) в host отправляется FOCUS 0, но локальный g_focus
не сбрасывается. Поэтому после mp.gui.cursor.show(false, false):

  browser.focused может остаться true;
  mp.browsers.focused может вернуть старый browser;
  JS и реальный Chromium расходятся по состоянию.

Исправление:

  - после отправки blur присвоить g_focus = 0;
  - проверить mouse target и состояние зажатых кнопок;
  - добавить native JS regression:
      focus -> скрыть общий cursor/input -> focused === false,
      mp.browsers.focused === null.


[P1] 2.2. Focus не возвращается в Chromium после crash recovery
----------------------------------------------------------------

Файл:
  native/legacy-3889/client/src/browser.cpp

Место:
  TakeEvents(), восстановление host, около строк 765–776.

При перезапуске host заново отправляются NEW, SHOW и RATE, но FOCUS для
g_focus не отправляется. Если API оставляет g_focus ненулевым, JS говорит
focused=true, а новый Chromium browser фактически focus не получил.

Нужно выбрать и зафиксировать один контракт:

  Вариант A, рекомендуемый: при падении host сбрасывать focus в 0 и требовать,
  чтобы меню повторно вызвало focus() после browserRestored/browserDomReady.

  Вариант B: после NEW восстановить FOCUS для старого g_focus, но только если
  browser visible, inputEnabled и общий CEF input/cursor действительно активен.

Добавить regression с настоящим завершением flovmp-cef.exe. Тест должен
проверять не только события crashed/restored, но и согласованность focused.


[P1] 2.3. browser.bounds расходится с native-геометрией
------------------------------------------------------

Файл:
  native/legacy-3889/client/src/script.cpp

Место:
  setter bounds, около строк 751–762.

Проверка выполняется до Math.trunc и без ограничения 7680:

  setBounds(0, 0, 0.5, 100) проходит проверку, затем width становится 0;
  native трактует width <= 0 как reset fullscreen;
  JS при этом хранит bounds.width === 0.

Также setBounds(..., 999999, ...) сохраняет в JS 999999, а native молча
ограничивает сторону до 7680. Getter снова не отражает реальное состояние.

Исправление:

  - сначала Number + Math.trunc;
  - после trunc требовать width >= 1 и height >= 1;
  - x/y ограничить диапазоном -7680..7680;
  - width/height ограничить 1..7680;
  - именно нормализованные значения хранить в this._bounds и отправлять native;
  - добавить тесты для 0.5, NaN/Infinity, отрицательных размеров и >7680.


[P2] 2.4. Лимит восстановления CEF исчерпывается навсегда за сессию
------------------------------------------------------------------

Файл:
  native/legacy-3889/client/src/browser.cpp

Место:
  StartHostLocked/TakeEvents, g_restarts.

g_restarts учитывает первый запуск и разрешает максимум три запуска процесса,
то есть после двух падений HUD больше не восстановится до полного Shutdown.
Нет cooldown, окна времени, сброса после долгой стабильной работы и отдельного
финального события/сообщения серверному UI.

Это не обязательно срочно переписывать перед первым E2E, но контракт должен
быть явным. Для production лучше:

  - exponential backoff;
  - лимит попыток внутри временного окна;
  - сброс счётчика после стабильной работы;
  - событие browserHostRecoveryFailed и понятная запись в лог.


[P2] 2.5. Метрики renderWidth/renderHeight неоднозначны
-----------------------------------------------------

При разных bounds GetStats возвращает максимум ширины и максимум высоты среди
разных surfaces. Такая пара может не быть размером ни одного реального browser.
Для диагностики владельцу полезнее добавить per-browser stats или назвать поля
maxRenderWidth/maxRenderHeight. На работу multiplayer это не влияет.


3. ГЛАВНЫЕ НЕЗАКРЫТЫЕ ПРОДУКТОВЫЕ ПРОВЕРКИ
==========================================

[P0] 3.1. Живой GTA Legacy b3889 E2E
------------------------------------

Обязательный сценарий на реальной GTA 1.0.3889.0:

  1. Чистая установка и вход через connect.cmd/play.cmd.
  2. Два настоящих клиента одновременно входят на один сервер.
  3. Оба видят друг друга; движение, стриминг, урон, смерть и respawn совпадают.
  4. Машина видна обоим; вход/выход/места/урон/двигатель синхронны.
  5. Владелец машины выходит и отключается: машина не исчезает, ownership
     корректно передаётся.
  6. HUD, modal, z-order, прозрачный click-through, focus/blur.
  7. После закрытия UI мышь и клавиатура полностью возвращаются игре.
  8. Esc открывает меню поверх живого мира и не останавливает сеть.
  9. F12 никогда не открывает Rockstar overlay.
 10. Alt-tab, resize, fullscreen/windowed, DPI 100/125/150%, кириллица,
     clipboard и ввод текста.
 11. Завершить flovmp-cef.exe: HUD восстанавливается без реконнекта.
 12. Reconnect/смена сервера: cookies/localStorage прошлого сервера не видны.
 13. Записать FPS, p95/p99 frametime, RAM/VRAM/CPU без HUD и с HUD.

До успешного прохождения нельзя честно писать «полная поддержка b3889».

Зелёная локальная сборка не доказывает, что VDS/CDN уже содержит эти бинарники.


[P0/P1] 3.3. Roadmap, пункт 4 — моды и карты
-------------------------------------------

Кодом сделаны server manifest/SHA-256/HTTP Range и клиентский mods-sync.ps1.
Но пункт не закрыт продуктово: живой запуск GTA с реальным data-only модом и
OpenIV.asi ещё не проверен.

Минимальный тест:

  - чистая GTA без server mods;
  - сервер отдаёт один небольшой безопасный тестовый мод;
  - докачка с обрывом и продолжением;
  - неверный SHA блокирует запуск;
  - обновление мода заменяет только нужный файл;
  - пользовательские mods уходят в backup и возвращаются при удалении;
  - .asi/.dll/.exe/скрипты сервер никогда не раздаёт;
  - GTA реально загружает мод и входит на сервер.

Итоговая готовность пункта 4: код примерно 85–90%, продуктовая готовность до
живого теста — не более 70–75%.


[P0/P1] 3.4. Roadmap, пункт 8 — серверное владение транспортом
-------------------------------------------------------------

Сделаны registry/protocol, API геймода, IPlayer.Vehicle и persistence. Клиентский
код есть, но ownership migration в двух настоящих GTA-клиентах не доказан.

Минимальный тест:

  - два клиента видят одну серверную машину;
  - водитель/пассажир и смена мест;
  - водитель выходит из радиуса, умирает и отключается;
  - ownership передаётся без исчезновения/телепорта/дублирования;
  - повреждения, двери, замок, двигатель и сирена переживают передачу;
  - stream-out/stream-in отдаёт полный актуальный snapshot;
  - рестарт сервера восстанавливает persistent state без дублей.

Итоговая готовность пункта 8: код примерно 90–95%, продуктовая готовность до
двухклиентского E2E — около 75–80%.


4. БЕЗОПАСНОСТЬ, КОТОРУЮ ЕЩЁ НЕ НАДО НАЗЫВАТЬ ЗАКРЫТОЙ
======================================================

[P1] Подписанная идентичность server package
--------------------------------------------

Сейчас есть точный origin allowlist и SHA-256/digest пакета. Это защищает от
случайной порчи и ограничивает сеть CEF, но не является полноценной
криптографической идентичностью игрового сервера.

Для сильной схемы нужны:

  - подписанный manifest;
  - доверенный public key/root в клиенте;
  - server identity;
  - версия, expiry и anti-rollback;
  - ротация ключей.

Не писать покупателю «криптографически подписанный server package», пока этот
путь не реализован и не протестирован.


5. ЧТО УЖЕ ЗАКРЫТО — НЕ ПЕРЕДЕЛЫВАТЬ
====================================

  - отдельный Chromium process и Windows sandbox;
  - уникальный cache/profile между процессами и серверами;
  - exact origin allowlist, default deny, запрет bridge во внешнем iframe;
  - shared-memory staging + seqlock;
  - настоящий z-order, прозрачный hit-test и inputEnabled;
  - frameRate 1–60, hidden browser без композитинга;
  - caps: максимум 12 browser и общий pixel-budget;
  - снижение внутреннего разрешения при перегрузе;
  - rate limits событий UI;
  - crash recovery host;
  - per-browser bounds/focus/lifecycle — код и integration-тесты готовы,
    кроме дефектов 2.1–2.3 выше;
  - кастом HTML/CSS/JS/Canvas/WebGL, ники/HP/armor/HUD/меню без правки ASI.

Не возвращать no_sandbox=true, общий Chromium profile, wildcard origins,
bridge во внешний iframe и произвольный remote URL.
