## 1. Что это за продукт

**FloV:MP** — самостоятельная мультиплеерная платформа для GTA V, которую
владелец продаёт как **лицензионный продукт** (не как хостинг). Клиент
получает серверный пакет + свой игровой клиент и ключ лицензии.

Два слоя, которые нельзя путать:

- **платформа FloV:MP** — движок, клиент, лицензирование, поставка;
- **геймод клиента** — его RP-логика в папке `gamemode` (C#), платформа её
  не содержит.

Почему так: RAGE:MP и alt:V закрыты по требованию Take-Two. Платформа
работает поверх локальных бинарников alt:V 16.4.39 полностью автономно, без
обращения к их инфраструктуре. Юридический риск владелец принял осознанно,
поднимать эту тему заново не нужно.

**Главное требование владельца (дано явно):** при любой неясности задавать
вопрос списком уточнений, ничего не делать молча по догадке.

### Как устроен игрок 3889

У игрока на b3889 **нет сущности движка alt:V**. Он приходит по своему
протоколу **FLOV/2** (TCP, поля через табуляцию, лимит строки 4096 байт) на
шлюз «игровой порт + 10» (по умолчанию 7798). Голос — UDP на том же порту.

Чтобы код сервера не раздваивался, такой игрок оборачивается в
`NativePlayerProxy` (`DispatchProxy`), который прикидывается `IPlayer`:
чтение берётся из последнего STATE, запись превращается в сообщения
протокола. **Важно:** этот объект нельзя передавать в движок alt:V (у него
нет нативного указателя) — такие места проверяются через `IsNative`.

Ограничения прокси: `Vehicle` всегда `null`, `Seat` всегда 0 — транспорт
3889 живёт в игре игрока, а не в движке. Это главный архитектурный долг
(пункт 8 roadmap).

### Синхронизация

- клиент шлёт `STATE` 20 раз в секунду (позиция, скорость, флаги, оружие,
  транспорт, здоровье, броня, модель);
- сервер рассылает соседей по радиусу `sync.stream_radius` (400 м) и лимиту
  `sync.max_streamed` (150), с частотой по дальности (50/100/200 мс), не
  отправляя неизменившееся;
- очередь отправки сессии — **неограниченный** канал со счётчиком
  (`NativeSession.OutboxCapacity = 4096`): отставший клиент отключается с
  причиной, но строки не теряются молча (раньше теряли — это чинили);
- снимок мира (объекты карты) шлётся **порциями** по мере опустошения
  очереди: 20 000 объектов доходят за 0,4 с.

### Бой (важно: изменено вчера)

Здоровье и броню **считает сервер**. Клиент присылает `HIT`, сервер
проверяет: существование жертвы, измерение, god-mode, живость стрелка,
дистанцию (от `sync.stream_radius` + запас), ближний бой (≤6 м, урон ≤60),
наезд (≤20 м), совпадение оружия с тем, что в руках по STATE (с окном 2 с
на смену оружия), частоту (60 попаданий/с, 1000 урона/с, 300 урона на одну
жертву в секунду). Затем сервер сам раскладывает урон на броню и здоровье,
шлёт жертве `DAMAGE` + `HEALTH` (+ `ARMOR`, только если изменилась) и при
нуле **сам объявляет смерть**, не дожидаясь клиента. Заявка клиента о своём
здоровье принимается, только если она **ниже** серверной.

### Лицензирование

- RSA-3072, закрытый ключ только на VDS (`/etc/flovmp-license/authority.pem`);
- ключ вида `FLV-8-8-8-8`, статусы: выдан / активирован / приостановлен /
  отозван; лимит серверов и слотов на ключ; срок или бессрочно;
- сервер активируется при первом запуске, дальше раз в 5 минут продлевает
  подписанный lease на 24 часа;
- **отказ (403) подписывается**, и клиент верит мгновенному отзыву только с
  подписью (иначе по открытому HTTP посредник выключал бы чужие серверы);
- отсрочка офлайна считается от подписанного срока последнего подтверждения
  (раньше — от даты файла `license.flv`, что позволяло `touch` обходить
  проверку бесконечно).

### Поставка

- пакеты собираются `scripts/pack_server.py` (Windows zip + Linux tar.gz),
  подписываются `scripts/distribution/sign_release.py` (ключ релизов —
  только на ПК владельца, `%USERPROFILE%\.flovmp\release-signing.pem`);
- публикуются на **VDS** (`publish_release_vds.py` через REDL) и на
  **GitHub**: https://github.com/shizeexgod/FloV-MP-releases (публичный);
- клиент ставит одной командой (`get.ps1`, режимы: VDS или `-GitHub
  owner/repo`, плюс `-Tag` для конкретного релиза) либо архивом
  `flovmp-setup.zip` в один клик;
- установщик проверяет SHA-256 каждого файла, делает резервную копию,
  откатывается при ошибке и **не трогает** файлы клиента (`config/flovmp.env`,
  `server/config/*`, `gamemode`, `license.flv`, ресурсы, миграции от 100).

Замер на живом сервере: при открытом меню сервер получает **186 состояний за
12 с** — столько же, сколько без меню (до фикса был 1).

**Оверлей Rockstar (F12).** Перехват оконных сообщений не помогал: игра

## 6. Где ещё искать баги (проверенные зацепки)

1. **Транспорт**: `IPlayer.Vehicle` = `null` для 3889; машина исчезает у
   остальных при выходе водителя; нет передачи владения. Смотреть
   `StarterResource.Native.cs` (`AuthorizeVehicleState`, `_nativeVehicleOwners`)
   и `native/legacy-3889/client/src/game.cpp` (`EnsureRemoteVehicle`,
   `UpdateRemote`).
2. **Synced metadata**: `SetLocalMetaData` у 3889 кладёт значение в словарь
   сервера и до других игроков не доходит — свои ники/полоски/значки на этом
   не построить.
3. **Снимок при stream-in**: сейчас соседи приходят строками PADD/PSTATE без
   единого снимка состояния (двери, тюнинг, metadata). Повторный вход в зону
   видимости может давать неполную картину.
4. **Античит**: `FLOVMP_ANTICHEAT=log` по умолчанию — в строгом режиме
   возможны ложные срабатывания на самолётах (порог считается от
   `MaxVehicleSpeedMps * 2`). Проверить до включения `kick`.
5. **Смешанные клиенты**: засчёт убийства требует подтверждённого нашего
   HIT — убийство игроком с клиента alt:V не засчитается. Проверить, если
   смешанный режим кому-то нужен.
6. **Голос**: относительно свеж (сетка ячеек, токен, IP-привязка). Под
   нагрузкой 20+ говорящих не проверялся.
7. **Раздача файлов с VDS**: у владельца большие загрузки с
   `188.127.229.224` обрываются на ~30 КБ (проверено четырьмя способами,
   локально на VDS файл отдаётся на 1,6 ГБ/с). На VDS клиента канал другой,
   но помнить об этом.
8. **VDS нестабилен**: периодически отваливаются и HTTP, и SSH через REDL
   (перегрузка хоста провайдера). Скрипты повторяют, но проверяй результат.

## 9. Грабли, на которые уже наступали

1. **Heredoc в Bash съедает обратные слэши** — `\\` превращается в `\`,
   `\f` в перевод формата. Для файлов с путями Windows используй Write/Edit
   или python с якорями без слэшей. Проверено на четырёх поломанных файлах.
2. **PowerShell 5.1 без BOM** читает кириллицу как ANSI — файлы `.ps1`
   сохранять в `utf-8-sig`.
3. **`dotnet build` без `-c Release`** кладёт DLL в `bin/Debug`, а сервер
   берёт из `bin/Release`. Несколько часов ушло на «почему правка не
   применяется».
4. **Деплой руками — только парой `FloVMP.Starter.dll` + `FloVMP.Core.dll`**,
   иначе `MissingMethodException` при входе игрока.
5. **REDL `/write` выше ~50 КБ** отвечает «записал», но файла не создаёт.
   Кусок держим 40 КБ и сверяем каждый по размеру (`deploy_vds.py`).
6. **Тесты с фиксированной датой** ломаются на следующий день — в
   `LicenseAuthorityTests` часы идут от `DateTime.UtcNow`.

## 10. Как работать

- Русские сообщения коммитов, по делу, с объяснением «почему», а не «что».
- Код и комментарии — на русском, в стиле существующего кода: объяснять
  неочевидное и причины, не пересказывать строки.
- Каждый раунд правок — коммит; `git push` только по явной просьбе владельца.
- Дизайн (UI, загрузочный экран) **не трогать** без владельца.
- Всё, что меняет поведение игры, проверять: боты дают 80 % покрытия без
  запуска GTA, замеры состояний (`PSTATE` за N секунд) — честный индикатор
  «мир живой / мир на паузе».
- Перед сдачей клиенту: `dotnet test`, сборка пакетов, подпись, публикация,
  и обязательно установка в пустую папку той же командой, что получает
  клиент.
