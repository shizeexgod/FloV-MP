# Серверный реестр транспорта — протокол FLOV/2 (ЧЕРНОВИК на согласование)

Пункт 8 roadmap, линия **1.0.6-beta**. Статус: **не утверждён владельцем**,
реализация сообщений начинается только после согласования имён и порядка
полей. Основа — набросок владельца от 24.09.2026; всё, что добавлено сверх
него, помечено «**+**» и вынесено в вопросы в конце.

## Принятые решения (от владельца, 24.09.2026)

- Сервер — владелец машины. `/car` и API создают машину в реестре.
- Машина трафика в реестр не попадает, пока в неё не сел игрок; тогда
  клиент шлёт `VREQ`, сервер выдаёт ID, игрок становится водителем.
  Ограничения: одна регистрация в 2 с на игрока, общий потолок
  `vehicles.max_registered` (по умолчанию 1000).
- Здоровье кузова и двигателя — серверные поля: от водителя принимается
  только вниз, вверх — только командой сервера (ремонт).
- Совместимость: клиент с версией из `HELLO` ниже 1.0.6 работает через
  поля машины в `STATE`, как в 1.0.4/1.0.5; от 1.0.6 — через реестр.
  Старый путь убираем после 1.0.7.
- Сохранение (8d, последним): платформенная таблица, миграция с номером
  меньше 100, только для машин с `persistent: true`.

## Сообщения

Числа — как везде в FLOV/2: `0.###`, инвариантная культура. Углы — градусы,
как `rx ry rz` у `STATE` в машине. Булевы — `0`/`1`.

### Сервер → клиент

| Сообщение | Поля | Когда |
|---|---|---|
| `VADD` | `id model x y z rx ry rz dimension flags plate` | вход машины в зону видимости (полный снимок); повторный вход — снова `VADD` |
| `VSTATE` | `id x y z rx ry rz vx vy vz engineOn sirenOn locked bodyHp engHp` | только если что-то изменилось; частота по дальности, как у `PSTATE` |
| `VDEL` | `id` | выход из зоны видимости или удаление машины |
| `VOWN` | `id playerId seat` | кто сидит на месте; `seat -1` — водитель; **+** `playerId 0` — место освободилось |
| **+** `VREG` | `reqId id` | ответ на `VREQ`: машина зарегистрирована |
| **+** `VREJ` | `reqId причина` | ответ на `VREQ`: отказ (лимит частоты, потолок, модель) |
| **+** `VSET` | `id engineOn sirenOn locked bodyHp engHp` | команда сервера **водителю**: применить значения (ремонт, заглушить, закрыть); единственный путь «вверх» для здоровья |

`flags` в `VADD` (битовая маска): 1 — двигатель, 2 — сирена, 4 — закрыта,
**+** 8 — сохраняемая (информационно для клиента не нужна — вопрос 6).
`plate` — до 8 символов, экранируется как обычная строка.

### Клиент → сервер

| Сообщение | Поля | Правило |
|---|---|---|
| `VREQ` | **+** `reqId` `model` | игрок сел за руль машины трафика; позиция берётся из его последнего `STATE`, измерение — его |
| `VSYNC` | `id x y z rx ry rz vx vy vz engineOn sirenOn bodyHp engHp` | только текущий водитель; от не-водителя — отброс + журнал античита; `bodyHp`/`engHp` — только вниз |
| **+** `VENTER` | `id seat` | игрок сел в зарегистрированную машину (сервер проверяет: дистанция, замок, место свободно) |
| **+** `VLEAVE` | `id` | игрок вышел |

### Как это сочетается со `STATE` у клиента 1.0.6+

**+** Клиент 1.0.6+ в машине реестра продолжает слать `STATE` (позиция
пешехода нужна для интереса, голоса, урона), но в поле `vehOwner` кладёт
**ID машины реестра**, а `vehModel` — её модель. Сервер для такого клиента
трактует `vehOwner` как ID машины и сверяет с реестром (вопрос 1).

## Смешанный онлайн (один релиз)

**+** Старые клиенты (< 1.0.6) продолжают видеть машины через `PSTATE`
водителя: для машины реестра с водителем сервер подставляет в его `PSTATE`
для старых получателей `vehModel` и `vehOwner = ID водителя`, как сейчас.
Машину реестра **без водителя** старый клиент не видит — это ограничение
одного переходного релиза (вопрос 4).
