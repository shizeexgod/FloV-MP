# Лаунчер: система CDN-манифеста (задача #8)

Обновлено: 2026-08-28
Статус: **логика готова и покрыта тестами (6/6 зелёных), подключена в UI. Реального CDN пока нет — тестируется на локальной «раздаче» (папка-как-CDN).**

## Зачем

Раздача и поддержание в актуальном состоянии **ядра клиента alt:V** (85
файлов) на машинах игроков — CDN alt:V мёртв, раздаём сами. Тот же механизм
позже раздаёт патчи и offset-конфиги совместимости (Вариант 1).

> Серверные ресурсы (`flovmp-core`, `flovmp-client`) через это НЕ идут — их
> клиент alt:V тянет с нашего сервера сам при подключении.

## Формат манифеста

`manifest.json` (генерируется `scripts/make-manifest.ps1`):

```json
{
  "version": "recon-17of85",
  "branch": "release",
  "baseUrl": "https://cdn.example/flovmp/client/",
  "files": [
    { "path": "altv-client.dll", "sha256": "54c7…", "size": 52611704, "url": "" }
  ]
}
```

- `path` — относительно корня управляемой папки, разделитель `/`.
- `sha256` — hex в нижнем регистре, потоковый SHA-256.
- `url` — пусто → берётся `baseUrl` + `path`. Можно указать абсолютный
  (файл лежит на другом хосте).
- `baseUrl` — http(s) корень **или** локальный путь (офлайн-тесты). Пусто →
  лаунчер берёт за базу расположение самого манифеста.

## Код (`FloVMP.Launcher.Core/Services/Cdn/`)

| Файл | Роль |
|---|---|
| `ManifestModels.cs` | `Manifest`, `ManifestEntry` |
| `ManifestClient.cs` | загрузка манифеста (http / локальный файл / `file://`), подстановка implicit base |
| `ContentHasher.cs` | потоковый SHA-256 |
| `SyncPlanner.cs` | сверка папки с манифестом: `Ok / Missing / WrongSize / WrongHash` + список «лишних» файлов (не удаляем, только отчёт) |
| `FileDownloader.cs` | параллельная загрузка (конфигурируемая конкурентность), докачка через HTTP `Range`, ретраи с экспон. backoff, `.part` → атомарный `Move`, проверка SHA-256 после скачивания; поддержка http и `file://` |
| `SyncService.cs` | `CheckAsync` (только проверка) и `SyncAsync` (проверка → докачка недостающего/битого → повторная проверка); `IProgress<string>` лог + `IProgress<DownloadProgress>` прогресс |

## Тесты (`FloVMP.Launcher.Tests/CdnSyncTests.cs`)

Все на локальной «раздаче» (temp-папка), 6/6 зелёные:
- актуальная папка → `UpToDate`;
- классификация `Missing / WrongSize / WrongHash`;
- `SyncAsync` докачивает отсутствующее и чинит битое;
- прогресс доходит до 1.0, счётчик файлов сходится;
- при неверном ожидаемом хэше — ретраи, затем провал, `.part` подчищен,
  целевой файл не подставлен;
- манифест без `baseUrl` резолвится от своей папки.

## Скрипт упаковки

```powershell
powershell -File scripts/make-manifest.ps1 -SourceDir runtime\client -OutFile runtime\client\manifest.json -Version dev-1 -BaseUrl https://cdn.example/flovmp/client/
```

Для реального деплоя: залить дерево папки на CDN, `-BaseUrl` = публичный корень.

## UI

Секция «ОБНОВЛЕНИЕ ЯДРА ПО МАНИФЕСТУ»: поле URL/путь + кнопка
«Проверить / Обновить» + прогресс-бар + статус (файлы, МБ, МБ/с). Настройка
`CoreManifestUrl` в `launcher.settings.json`. Управляемая папка по
умолчанию — `%LOCALAPPDATA%\FloVMP\client`.

## Осознанно НЕ сделано

- Пауза/докачка между сессиями по кнопке (Range-докачка на уровне одного
  запуска уже есть).
- Удаление «лишних» файлов (сейчас только репорт — безопаснее).
- Подпись манифеста (когда появится свой CDN — добавить, иначе MITM может
  подсунуть свой manifest+файлы; хэши защищают целостность набора, но не
  подлинность манифеста).
