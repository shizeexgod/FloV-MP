# Лаунчер: совместимость с патчами GTA V (задача #9)

Обновлено: 2026-08-28
Статус: **каркас готов, покрыт тестами (11 тестов). Своего хука/CDN пока нет — транспорт и файловая логика подмены рабочие.**

Rockstar патчит GTA V, offset'ы в памяти уезжают, хук клиента ломается.
Команды alt:V больше нет — адаптация целиком на нас (это бессрочная Фаза 4).
Два механизма, разного качества (из HANDOFF).

## Вариант 1 — Native Mode (лёгкие патчи)

Клиент работает на настоящем `GTA5.exe` из Steam/Epic. Лаунчер тянет с CDN
`compat.json` и сверяет установленную версию.

**Код** (`Core/Services/Compat/`):

| Файл | Роль |
|---|---|
| `GameVersion.cs` | детект версии `GTA5.exe`: PE FileVersion + размер (+ SHA-256 по запросу) |
| `CompatManifest.cs` | модели: `versions[]` (gtaFileVersion, gtaSize, status `Supported/Untested/Broken`, `offsets` map, `fallbackBuildId`, note), `cachedBuilds[]` |
| `CompatService.cs` | `FetchAsync` + `EvaluateAsync` → вердикт: `Ok / Untested / NeedsFallback / Unknown / NoManifest` |

**Вердикты в лаунчере** (перед запуском, если задан `CompatManifestUrl`):
- `Ok` — запускаемся;
- `Untested` / `Unknown` — предупреждение в лог, запуск не блокируется;
- `NeedsFallback` — **запуск отменяется**, в лог пишется, какой `cachedBuild`
  нужен для Варианта 2;
- `NoManifest` — «на свой риск», запуск не блокируется.

Поле `offsets` намеренно свободной формы (`string→string`): конкретную схему
задаём, когда появится собственный хук. Сейчас Вариант 1 = «знаем ли мы эту
версию и безопасно ли пускать».

## Вариант 2 — Fallback Mode (тяжёлые патчи): подмена GTA5.exe

Если версия `Broken` — временно подменяем `GTA5.exe` игрока кэшированным
стабильным билдом, после игры возвращаем оригинал.

**Инженерные меры безопасности (все реализованы в `GameExeManager`):**

1. **Атомарность.** Оригинал → `GTA5.exe.flovmp-orig` через `File.Move`
   (`MoveFileEx`); возврат через `File.Replace`. Не `copy+delete`.
2. **Маркер `PendingRestore`** (`%LOCALAPPDATA%\FloVMP\pending-restore.json`):
   пишется durable (tmp + атомарная замена) **до** любых файловых операций,
   снимается **только** после подтверждённого хэшом отката. Хранит пути,
   SHA-256 оригинала, время, PID игры.
3. **Проверка при старте.** `App.OnStartup` первым делом: если маркер есть —
   `GameExeManager.RestoreAsync()`, результат в лог UI.
4. **Отдельный watchdog-процесс.** `WatchdogSpawner` запускает тот же
   `FloVMP.Launcher.exe --watchdog <gamePid> <markerPath>` — без UI, ждёт
   выхода игры (`WaitForExitAsync`), откатывает. Переживёт падение UI.
5. **Бэкап не теряем.** Откат сверяет хэш восстановленного файла с
   `OriginalSha256`. Не сошлось / бэкапа нет / на месте не оригинал →
   маркер **не снимается**, честное сообщение «запусти лаунчер снова».
6. `SwapInAsync` отказывает, если уже есть маркер или уже есть бэкап
   (незавершённая прошлая подмена — нужен ручной разбор, не молча).

**Оговорка про копирайт** (из HANDOFF): хранение/раздача КОПИИ `GTA5.exe` на
своём CDN острее обычного модинг-инжекта. `cachedBuilds[].url` — точка, где
это подключается; решение владельца принято, здесь только транспорт.

## Тесты (`FloVMP.Launcher.Tests`)

- `CompatServiceTests` (5): Supported→Ok, матч по одной FileVersion,
  Unknown, Broken→NeedsFallback+build, нет манифеста→NoManifest.
- `GameExeManagerTests` (6): swap↔restore round-trip; **краш после подмены →
  чинится при следующем старте**; отказ при существующем маркере; no-op
  при совпадении билда; restore без маркера — no-op; restore чистит маркер,
  если оригинал уже на месте.
