## 2. Разрешение дилеммы: «Нужны ли разные физические серверы?»

### Позиция технаря заказчика
Технарь обоснованно опасается:
1. **L7 HTTP DDoS на сайт/форум:** Атака на порт 80/443 забьет сетевой шлюз и положит игровой сервер GTA.
2. **Взлом веб-CMS:** Компрометация сайта не должна давать root-доступ к базе данных и серверу игры.

### Инженерное решение FloV:MP (Без покупки 3 дорогих серверов)

Покупать 3 отдельных сервера **не требуется**. Лаунчеру отдельный сервер не нужен вообще (он работает по HTTP с Nginx).  
На имеющейся машине реализуется один из двух сценариев:

#### Вариант А: Гибридная изоляция (Рекомендуемый Enterprise)
- **Выделенный сервер AMD 64 ГБ:** Полностью отдаётся под игровой сервер `flovmp-server`, высокопроизводительный пул MariaDB и Nginx FastDL (раздача файлов лаунчеру по прямому линку с каналом 1–10 Гбит/с). Защита: Anti-DDoS уровня UDP.
- **Внешний микро-VDS ($5–10/мес, 2 ядра, 4 ГБ):** На нем крутится только публичный веб-сайт, форум и витрина доната, закрытые бесплатным или Pro тарифом **Cloudflare** (L7 Anti-DDoS). С базой данных микро-VDS общается через зашифрованный WireGuard/IPsec туннель.

#### Вариант Б: Виртуализация на одной машине (KVM / Proxmox / Docker)
Если заказчик хочет строго одну физическую железку, у хостинга заказывается **второй дополнительный IP-адрес**:
- **VM 1 / Контейнер 1 (Игровой стек, IP #1):** 6 ядер, 48 ГБ ОЗУ $\rightarrow$ FloV:MP Server, MariaDB.
- **VM 2 / Контейнер 2 (Веб и ассеты, IP #2):** 2 ядра, 16 ГБ ОЗУ $\rightarrow$ Веб-портал Next.js, Nginx FastDL. IP #2 проксируется через Cloudflare.

## 4. Требования к системному ПО: Почему Ubuntu 22.04 — ДА, а Apache — НЕТ

### Ubuntu 22.04 LTS — ИДЕАЛЬНО
- Нативная поддержка .NET 8 CoreCLR (`/usr/share/dotnet`).
- Проверенное ядро Linux 5.15/6.x с поддержкой современных алгоритмов перегрузки TCP BBR.
- Полная совместимость с эталонной сборкой FloV:MP на VDS `188.127.229.224`.

### Apache — КАТЕГОРИЧЕСКИ ЗАПРЕЩЁН
1. **Блокирующая модель:** При выходе обновления карты или модпака 200–500 игроков одновременно через лаунчер начинают скачивать архивы по 500 МБ – 2 ГБ. Apache порождает сотни процессов, переполняет лимиты дескрипторов и роняет сервер по Out Of Memory.
2. **Nginx — обязательный стандарт:**
   - Event-driven архитектура на `epoll` с директивой `sendfile on;` и `tcp_nopush on;`.
   - Раздает файлы тысячам клиентов на скорости 10 Гбит/с при потреблении ОЗУ менее 100 МБ.
   - Идеальный реверс-прокси для Next.js 14 и WebSocket/SSE соединений консоли и оффлайн-админки.

## 5. Изоляция и защита интеллектуальной собственности FloV:MP

При развертывании на серверах заказчика:
1. **Бинарная поставка:** Заказчик получает скомпилированные бинарники (`flovmp-server`, `coreclr-module.so`, dll-сборки гейммода). Исходный код C++ ядра и C# не передаётся.
2. **Лицензирование:** Сервер валидирует ключ `FLV-XXXX-XXXX-XXXX` и сверяет разрешенный IP через защищенный SaaS эндпоинт FloV:MP.
3. **Безопасность Linux (`systemd` Sandbox):**
   - Выделенный пользователь `flovmp` (без sudo и shell `/bin/false`).
   - Флаги изоляции сервиса:
     ```ini
     [Service]
     User=flovmp
     Group=flovmp
     ProtectSystem=strict
     ProtectHome=true
     NoNewPrivileges=true
     ReadWritePaths=/opt/flovmp/flovmp-data /opt/flovmp/logs
     ```
   - Доступ к MariaDB ограничен базой конкретного проекта без прав администрирования СУБД.
