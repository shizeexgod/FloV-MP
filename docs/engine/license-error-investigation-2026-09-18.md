# `FAILED_TO_VERIFY_GAME_LICENSE`: расследование 18.09.2026

## Факты

- Сервер FloV:MP и пакет AI-Testing принимают TCP/HTTP на `7788`.
- `license.flv` сервера валиден; в серверном логе лицензия определяется до
  подключения игрока. Это не отказ лицензии FloV:MP.
- Клиентский лог показывает `Game version: 3337 on EGS`, хотя установленный
  Epic Legacy содержит `GTA5.exe` `1.0.3889.0` и RPF b3889.
- Тот же лог содержит `Rpf version: 3889 differs from alt rpf version: 3521`.
- Затем клиент получает `FAILED_TO_VERIFY_GAME_LICENSE` и сервер не пишет событие
  подключившегося игрока. Ранее launcher-лог подтверждал: `Backup file GTA5.exe
  is valid` и `Backup file copied`.

## Причина

Доступный native client 16.4.39 не совместим с текущим Legacy b3889. Старый
backup-flow дополнительно подменял exe кэшем b3337, оставляя установленные RPF
b3889. В результате игра запускалась в смешанном профиле, а проверка игрового
лицензионного контекста не могла завершиться корректно.

## Исправление в FloV:MP

1. `AltvToml` теперь пишет `autoBackup=false`.
2. `LocalCdn` возвращает `404` на весь `/backup/*` и не раздаёт Rockstar
   binaries.
3. `GtaLaunchGuard` останавливает Legacy, кроме подтверждённого b3521, и весь
   Enhanced до появления отдельного native-адаптера.
4. `--allow-unsupported` сохранён только для явного диагностического прогона.

Проверка на текущей установке: коннектор завершился кодом `2` до запуска GTA,
указал `legacy-native-adapter-missing`, и `GTA5.exe` остался неизменённым.

## Что ещё требуется для настоящей поддержки b3889/Enhanced

Нужен отдельный совместимый native client/adapter и end-to-end прогон: окно
GTA остаётся живым, client runtime подключается, сервер видит игрока, загружаются
ресурсы, работает авторизация и два клиента видят друг друга. Изменения C#-сервера
или `license.flv` не могут заменить этот компонент.
