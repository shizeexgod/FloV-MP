# Контракт видимости и синхронизации игроков

## Что подтверждено кодом

При `OnPlayerConnect` ресурс `flovmp-starter`:

1. принимает игрока после проверок имени, бана и лимита лицензии;
2. задаёт модель `mp_m_freemode_01`;
3. вызывает `player.Spawn(_spawnPosition, 0)` в стандартном dimension `0`;
4. задаёт здоровье, броню и поворот.

После этого игрок является обычной server-side player-сущностью движка. Отдельный
клиентский клон игрока не создаётся: движок сам передаёт ближайшие player-peds,
а клиентский ресурс использует `alt.Player.streamedIn` для ESP и защитных
операций. Это правильная схема для сетевой синхронизации, если native runtime
совместим с установленной версией GTA V.

## Фактические границы гарантии

Текущий эталонный `server.toml` задаёт:

- `streamingDistance = 250` — игрок вне этого радиуса не обязан быть создан на
  клиенте как streamed-in entity;
- dimension должен совпадать; `/setdim` намеренно разделяет виртуальные миры;
- `maxStreaming.peds = 48` — общий пул ближайших peds, куда входят player-peds
  и server-side NPC peds;
- `syncSend`/`syncReceive` — потоки транспорта состояния, а не расширение
  радиуса видимости.

Поэтому продукт может гарантировать: игрок видит других игроков, находящихся в
том же dimension, в радиусе стриминга и попавших в ближайший pool. Нельзя
гарантировать одновременную отрисовку всех 2000 слотов на одном экране.

## Что не подтверждено на текущем Mac

Статический код-аудит и клиентские симуляции не доказывают живой E2E. Для
закрытия коммерческого acceptance-gate нужны два Windows-клиента на чистом
поддержанном GTA-профиле:

1. оба клиента подключаются к одному серверу;
2. оба получают player entity другого клиента;
3. движение/поворот одного видны второму минимум 60 секунд;
4. выход одного удаляет его entity у второго;
5. повторный вход снова создаёт entity без перезапуска сервера.

Пока native-адаптер Legacy b3889 и Enhanced не подтверждены, этот gate остаётся
`false`, даже если серверный код и конфигурация корректны.

## Диагностические признаки

- серверный лог: `Игрок ... подключается...` для каждого клиента;
- клиентский F8/netgraph: наличие streamed player entity и отсутствие сетевых
  таймаутов;
- на сервере `online` показывает число подключений, но не заменяет проверку
  визуальной синхронизации;
- ESP в FloV:MP читает `alt.Player.streamedIn`, поэтому может использоваться
  только как дополнительный индикатор — не как отдельный механизм спавна.
