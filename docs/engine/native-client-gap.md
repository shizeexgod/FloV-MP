# Native-клиент: текущий разрыв до поддержки Legacy и Enhanced

Обновлено: 2026-09-18

## Что подтверждено локально

Рабочий сервер FloV:MP на базе сохранённого server runtime запускается автономно,
слушает порт `7788`, загружает C#-ресурс Florida V и клиентский JS-ресурс.

В клиентской папке FloV:MP сейчас есть:

- `altv.exe` ProductVersion `16.3.7`;
- `altv-client.dll` ProductVersion `16.4.39`;
- `altv-launcher-patcher.dll`;
- полный набор CEF/V8-зависимостей.

Для Legacy 3521 есть изолированный staging-профиль. Проверка RPF и проверка
backup-файлов проходят, патчер сообщает `Patching finished`, но GTA не доходит до
игрового окна. В системном журнале предыдущего запуска также зафиксирован
отдельный `altv.exe` с исключением `0xc0000005`; это не доказательство, что причина
одна и та же, поэтому эти случаи не объединяем без нового трассирования.

18.09 staging `C:\FloV-MP\runtime\gtav-3521-staging` проверен отдельно:
в нём 1145 файлов / 55,6 ГиБ, тогда как в установленной копии есть ещё 200 путей,
включая большие DLC RPF. Это не готовая игровая установка, а частично собранный
depot. Явный `--platform steam` теперь корректно выбирает Steam во всей цепочке,
но полный Legacy content необходимо докачать после интерактивной авторизации
владелецкого Steam-аккаунта. `271591` содержит лишь малый набор исполняемых
файлов; полный content depot — `271594` с manifest
`6991706980502578342`. До этого Legacy 3521 также не считать E2E-готовым.

Для текущей Enhanced-установки есть только `GTA5_Enhanced.exe` и её RPF-файлы.
Совместимого native client/runtime, который подтверждённо умеет загрузить Enhanced,
в доступных локальных сборках нет.

Для планирования зафиксирован отдельный Enhanced-профиль `1.0.1158.13`
(`runtime/compat/enhanced-1158`). Это не «Enhanced 3889»: номера Legacy и
Enhanced независимы. Профиль намеренно не содержит выдуманных SHA-256 — их надо
снять с чистой Windows-установки через `scripts/verify-enhanced-1158.ps1`.

Текущий Epic Legacy владельца — `GTA5.exe` `1.0.3889.0` (RPF b3889), а
доступный client runtime 16.4.39 рассчитан на Legacy b3521. Старый локальный
backup-flow отдавал кэшированный `GTA5.exe` b3337; это смешивало exe и RPF.
С 18.09 коннектор пишет `autoBackup=false` и останавливает неподдерживаемый
профиль до запуска игры. При явной диагностике endpoint `/backup/update.json`
отдаёт корректный native-манифест `{"files":[]}`: launcher требует это поле даже
при выключенном backup-flow, а 404 или общий CDN JSON обрывают запуск с `0x30,033`.
Манифест пустой, поэтому никакие Rockstar-файлы не скачиваются и не подменяются.

Живой прогон 18.09 после исправления прошёл CDN, восстановление EOS и фазу
`Launcher patch completed`, но GTA5.exe 3889 так и не появился, а
`client_*.log` не был создан. Значит, сбой находится в закрытом native bootstrap
до загрузки `altv-client.dll`, а не в сервере, `license.flv` или CDN. Коннектор
распознаёт этот признак через 20 секунд, завершает оставшийся bootstrap-процесс и
пишет точный диагноз вместо ожидания 240 секунд.

Этот путь проверен живым тестом: после `Launcher patch completed` диагностика
сработала, `flovmp.exe` и коннектор завершились, а временный
`commandline.txt.renamed` был очищен. GTA5.exe и `client_*.log` по-прежнему не
появились, то есть граница native bootstrap подтверждена повторно.

## Что нельзя считать решением

- замена только `GTA5.exe` или только RPF между Legacy и Enhanced;
- смешивание произвольных версий `altv-client.dll`, launcher и patcher;
- отключение ошибок магазина или античита как способ “починить” совместимость;
- запуск Enhanced через Legacy-профиль без отдельного native-теста.

## Требуемый компонент для следующего этапа

Нужен отдельный технически проверяемый вариант для каждого издания:

1. согласованный native client FloV:MP с поддержкой конкретного Legacy-билда и
   отдельным модулем для конкретного Enhanced-билда;
2. самостоятельный native compatibility layer для каждого издания, с отдельными
   сигнатурами/адаптерами и автоматическим выбором профиля в лаунчере.

### Минимальный контракт адаптера Legacy b3889

Для профиля `runtime/compat/legacy-3889/native-profile.json` адаптер должен
работать с Epic Legacy `1.0.3889.0` и принимать только подтверждённые
fingerprint-ы exe/RPF из этого профиля. Он не должен скачивать или подменять
`GTA5.exe`, `update.rpf` или `update2.rpf`, а также использовать Steam-файлы
для Epic-установки.

До включения адаптера в лаунчер обязательны:

1. отдельные бинарники/манифесты native-клиента и launcher patcher для b3889;
2. явная версия адаптера `flovmp-legacy-native-3889` и проверка её хэшей;
3. запуск через штатный путь FloVMP с отключённым backup-flow;
4. пять E2E-проверок из раздела ниже на чистом профиле владельца.

Текущий `altv-client.dll` 16.4.39 и поставляемый вместе с ним `legacy.dll`
этот контракт не выполняют: их фактический предел b3521 подтверждён логом
`Rpf version: 3889 differs from alt rpf version: 3521`.

C#-сервер, ресурсы, NUI и лаунчер не могут заменить этот слой: они начинают
работать только после того, как GTA-процесс создан и client runtime подключён.

## Критерий закрытия разрыва

Для каждого издания нужен свежий end-to-end протокол:

1. GTA открывает игровое окно и остаётся живым;
2. client runtime подключается к `127.0.0.1:7788`;
3. сервер видит игрока и загружает `flovmp-client`;
4. игрок проходит авторизацию и появляется в мире;
5. два клиента видят друг друга и обмениваются движением.

До выполнения всех пяти пунктов поддержка соответствующего издания считается
неподтверждённой.
