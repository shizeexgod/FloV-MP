# База данных FloV:MP

Таблицы создаёт сам сервер при старте — вручную ничего импортировать не нужно.
Файлы в `migrations/` применяются по порядку ровно один раз; что уже применено,
записано в таблице `schema_migrations`. Не редактируйте применённые файлы:
сервер сверяет их контрольные суммы и сообщит о расхождении.

| Таблица       | Что хранит                                        |
|---------------|---------------------------------------------------|
| `bans`        | блокировки по Social Club, IP, HWID                |
| `admins`      | администраторы по SocialClubId, уровень 1–8        |

## Выдать себе права администратора

```sql
INSERT INTO admins (social_club, level, is_founder)
VALUES ('123456789', 8, 1)
ON DUPLICATE KEY UPDATE level = VALUES(level), is_founder = VALUES(is_founder);
```

- `social_club` — ваш SocialClubId (только цифры). Он виден в логе сервера при
  вашем подключении: `Игрок Имя (ID: 1, SocialClub: 123456789) подключается...`
- `level` — от 1 (помощник) до 8 (основатель).
- Права применяются в течение 30 секунд без перезапуска. Если сервер запущен
  в окне консоли (Windows, `FloVMP-Server.exe`), мгновенно — командой `reloadadmins`.

Снять права: `DELETE FROM admins WHERE social_club = '123456789';`
Администратор на дежурстве теряет права сразу после синхронизации.

Выдавать права по нику нельзя: ник задаёт сам игрок, и любой мог бы взять
ник администратора.

## Подключение к базе

Логин и пароль — в `config/flovmp.env` (`FLOVMP_DB_USER`, `FLOVMP_DB_PASSWORD`).
На Linux от root можно без пароля: `sudo mysql flovmp_server`.

## Своя схема для RP-сервера

Добавляйте свои таблицы отдельными файлами с номером больше последнего,
например `migrations/100_my_houses.sql`. Номера 001–099 зарезервированы
платформой: обновление может добавить туда новые файлы.

Если у пользователя базы нет прав на изменение схемы, отключите миграции
(`FLOVMP_DB_MIGRATE=0`) и применяйте файлы сами.
