# FloV:MP — план визуальной архитектуры

Статус: **Phase 1 / согласование направления.**

Основание: `FLOVMP_WEBSITE_REDESIGN_CLAUDE_PROMPT.txt`, аудит
`REDESIGN_AUDIT.md`, текущая реализация `web/` и предоставленные визуальные
референсы. Главный ориентир — принцип композиции RAGE Multiplayer: сильный
игровой контекст, простая навигация, воздух и последовательные editorial-блоки.
Это не задание на копирование RAGE:MP, его ассетов или текстов.

## 1. Зафиксированное направление

**Название направления: «Game-tech editorial».**

FloV:MP выглядит как продукт команды, которая делает технологическую основу
GTA V-проектов. Сайт не маскируется под CRM/крипто/AI-стартап и не превращается
в сайт отдельного RP-сервера. Визуальная формула:

```text
реальный игровой key-art + спокойная инженерная подача + один настоящий продуктовый интерфейс
```

Палитра: 85–90% графитовых нейтралей, 10–15% магенты. Розовый — только CTA,
фокус, выбранное состояние, тонкая световая точка и один акцент в visual.
Ни синих/фиолетовых декоративных градиентов, ни постоянного glassmorphism.

## 2. Новая структура главной страницы

| № | Блок | Композиция и задача |
|---|---|---|
| 1 | Hero | Левый столбец: короткое утверждение о независимой инфраструктуре, 2 действия. Правый: один большой GTA-oriented key-art. Ни статистики, ни панели из мелких карточек. |
| 2 | Начало работы | Два шага в одну строку: «Лицензия» → «Развёртывание». Это editorial-тimeline, а не две одинаковые карточки. |
| 3 | Управление проектом | Асимметричный текстовый блок слева и реальный screenshot FloV:MP Dashboard справа. Это основной product mockup. |
| 4 | Основа платформы | Три чередующихся широких блока: свой runtime, FastDL/launcher, защита и контроль. У каждого свой визуальный материал: инфраструктура, launcher/город, техническая схема. |
| 5 | Возможности | Не шесть равных карточек. Две ключевые возможности крупно + короткий горизонтальный список остальных с Lucide-иконками. |
| 6 | Для разработчика | Реальный C#/конфигурационный фрагмент из существующей документации, CTA к документации. Без выдуманного терминала. |

Страницы «Возможности», «Документация», «Лицензия», «Проекты», «Контакты»
остаются самостоятельными маршрутами. Главная ведёт к ним, а не пытается
повторить их целиком.

## 3. Header

```text
[ знак FloV:MP ]    Возможности  Лицензия  Проекты  Документация  Контакты        [ Войти / Кабинет ]
```

- Максимальная ширина 1360px, высота около 64px, без большой floating-capsule.
- Обычная горизонтальная навигация, тонкий нижний разделитель только при скролле.
- Один account-action в обводке справа; у авторизованного пользователя —
  «Кабинет», у гостя — «Войти».
- Убираются из header: RU/EN, выбор темы и вторые CTA.
- На телефоне: логотип, account-action и маленькое меню; раскрытие компактное,
  без гигантского full-screen drawer. Язык остаётся только в footer.

## 4. Hero и GTA visual

**Композиция:** левый текст занимает 42–46% desktop-ширины; справа — 54–58%
с одним глубоким key-art. Визуал частично уходит за правый край, но не образует
коллаж из маленьких парящих окон. За персонажами — затемнённый городской
вечерний план; поверх допускается только тонкий контур статуса соединения или
фрагмент launcher-интерфейса.

**Текстовая иерархия:** короткое трёхстрочное утверждение, 1 абзац до четырёх
строк, primary «Получить Lifetime» и secondary «Документация». Никаких
«платформа 2026», искусственных счётчиков и технического шума в первом экране.

**Нужный asset:** оригинальный/заказной визуал `public/site-redesign/hero/` в
широком формате 16:10 или PNG/WebP со слоем прозрачности. Не используем
официальный Rockstar key-art из чужого сайта. Пока asset отсутствует, hero
внедряется с нейтральным image placeholder того же размера — без абстрактного
куба и «орбит».

## 5. Dashboard mockup

Используется реальный `public/media/shot-dashboard-overview.png` либо
`shot-dashboard-projects.png`, а не нарисованная заново SaaS-панель.

- Объект стоит в правой половине секции, внутри тонкой browser-frame.
- Начальное положение: `rotateY(-4deg) rotateX(2deg)`; в viewport он мягко
  выравнивается почти до нуля. На desktop разрешён небольшой pointer tilt
  (не больше ±1.5°); на touch и reduced-motion — статичный плоский кадр.
- Под ним один спокойный graphite-shadow и тонкая magenta-reflection.
- Секция показывает только существующие функции кабинета: проекты/среды,
  консоль, ключи и метрики реального агента.

## 6. Где cards остаются, а где исчезают

**Остаются:** FAQ-аккордеон, компактные элементы возможностей, формы,
authentication, реальные сущности dashboard и небольшие legal-списки.

**Исчезают/пересобираются:** cards как фон каждого раздела главной, 6 равных
feature-cards, крупная карточка вокруг всего footer, карточки-обёртки для
обычных абзацев. Контент чередует открытые поверхности, горизонтальные линии,
полноформатное медиа и компактные списки.

## 7. Типографика и spacing

- Основной текст: **Manrope** (400/500/700), уже self-hosted и хорошо читает
  кириллицу. Это базовый UI/копирайт-фонт.
- Display: **Unbounded** только для hero, крупных title и редких цифр секций.
  Не использовать в длинном тексте, навигации и каждой карточке.
- Код, IP, ключи: JetBrains Mono.
- Контейнер: 1280–1360px; desktop side padding 32–48px; mobile 20px.
- Вертикальный ритм: 112–160px между крупными блоками desktop, 72–96px mobile.
- Радиусы: 10px для controls, 14–18px для UI-поверхностей, 22px только у
  hero/mockup. Никакой «капсулы» по умолчанию.
- Заголовки белые/светло-серые; градиент не применяется ко всем заголовкам.
  Акцентная строка или слово — только в hero/CTA.

## 8. Motion strategy

Выбранные паттерны после исследования библиотек/реестров:

| Источник | Берём | Почему |
|---|---|---|
| Motion / transitions.dev | transform/opacity reveal, interruptible state transitions | Лёгкая, доступная смена контента без scroll-jacking. |
| Magic UI / 21st | restrained light/glare treatment для одного mockup | Придаёт глубину настоящему dashboard, не создавая «glass everywhere». |
| React Bits / Aceternity | pointer-safe tilt и mask reveal как принцип, не как декоративный компонент | Подходит hero-media и screenshot, не нагружает UI. |
| Bklit | только будущие графики реальной телеметрии | Не используем как декоративную аналитику. |
| termcn | существующая консоль в dashboard | Не переносим терминальный стиль на маркетинговую страницу. |

Правила реализации:

- Reveal 300–450ms: opacity + `translateY(12px)`; без общего stagger на весь
  экран.
- Hero art: очень лёгкий parallax через transform; выключен на touch и
  `prefers-reduced-motion`.
- Mockup: perspective interpolation только при пересечении viewport.
- Кнопка: translateY(-1px), arrow translateX(2px), короткий sheen; без
  постоянного glow.
- Ссылки: underline/line-grow; header меняет только opacity/background при
  scroll.

## 9. Footer, legal и язык

Низ страницы имеет фиксированный порядок:

```text
Финальный CTA
→ собственный legal/disclaimer FloV:MP
→ компактная навигация (продукт / документы / поддержка)
→ © и Language: Русский / English
```

- Legal-текст свой и опирается на текущие документы FloV:MP. Не копируем
  формулировку RAGE:MP.
- Персональный телефон и личный Telegram не являются главным визуальным
  содержимым footer; реквизиты остаются на `/legal/requisites`.
- Снизу — простой текстовый RU/EN-переключатель, без флагов и большой пилюли.
- Theme toggle удаляется из основного header. Техническая поддержка темы может
  сохраниться, но dark является публичным default.

## 10. Mobile behaviour

- Hero сначала показывает copy и CTA, затем art в соотношении около 4:3;
  никаких боковых «system rails» на ширине < 1024px.
- Dashboard mockup становится плоским, получает horizontal crop только при
  сохранении читаемой части интерфейса; не сжимается до нечитаемого миниатюрного
  окна.
- Editorial-пары меняют порядок на «контекст → visual», а не на произвольный
  стек карточек.
- Навигация, CTA, языковой блок имеют touch target не меньше 44px.
- Большие visual lazy-load, а motion и blur снижены/выключены в reduced-motion.

## 13. Риски и защита качества

1. **Нет hero-art.** Без него не подменяем visual абстрактными сферами или
   чужим key-art; сначала готовим корректный asset.
2. **Тяжёлые медиа.** WebP/AVIF, `next/image`, явные размеры, lazy-load ниже
   fold; no WebGL.
3. **Локализация.** Каждый новый текст сразу добавляется в RU и EN, иначе
   изменение не принимается.
4. **Правдивость.** Нет fake stats, client logos, придуманных релизов или
   возможностей. Пустое состояние говорит правду.
5. **Доступность.** Keyboard/focus, alt, reduced-motion и читабельные контраст
   остаются обязательной частью каждого этапа.

## 14. Порядок реализации после фиксации

2. Hero: один качественный visual и copy; visual QA до перехода дальше.
3. Dashboard mockup и Getting Started.
4. Остальные editorial-секции и вторичные страницы.
5. Motion, mobile, performance, accessibility, build + browser QA.
