# Живой стенд: два ресурса в одном сервере

Всё, где участвуют два ресурса, доказывается **живым прогоном**, а не только
юнит-тестами: движок доставляет события и экспорты по своим правилам, и
тесты посредника этого не видят (так был пойман баг пункта 22, 7d932ab).

```bash
server/tools/live-bench/bench.sh /opt/flovmp-test 20 12 "restart probe-c"
```

- `/opt/flovmp-test` — тестовая установка (install.sh/get.sh); стенд
  подменяет в ней платформу свежей сборкой и добавляет ресурсы `probe-a/b/c`.
- `20` — сколько секунд работает сервер; дальше пары «через N секунд —
  команда в консоль сервера» (`stop`, `start`, `restart` ресурса).
- В контейнере без IPv6 (облако) движок падает «Failed to create host»;
  стенд сам подключает `v6shim.c` (LD_PRELOAD: AF_INET6 → AF_INET). В пакеты
  прослойка не входит.

Пробы: `ProbeB` — экспорты и события на голом AltV.Net; `ProbeC` — геймод
на `FloVMP.Sdk` (асинхронные обработчики, `FloVExports`); `ProbeA` — по
времени зовёт их и меряет промежутки между тиками. Меняйте пробы под то, что
проверяете.

## Что стенд уже показал (25.09.2026)

| Вопрос | Ответ живого прогона |
|---|---|
| Alt.Emit между ресурсами | доставляется после выхода отправителя из тика |
| Alt.Export/Import между C#-ресурсами | синхронно: тот же вызов, поток и тик; Task<T> проходит |
| Import до загрузки экспортёра / несуществующего | бросает InvalidImportException; в OnStart роняет сервер |
| Import с неверным типом | проходит; при вызове — FormatException (значения приводятся) |
| Старый импорт после restart экспортёра | зовёт код прежнего экземпляра |
| await внутри экспорта | продолжается в очереди вызывающего (FloVExports это исправляет) |
| FloVAsync: 300 мс «в базе» | 268 тиков прошло, промежуток ≤43 мс (синхронно — 309 мс простоя) |
| stop ресурса во время await | finally выполнен, Stop 6 мс |
